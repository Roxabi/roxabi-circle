# ADR-0014 — The published OpenAPI document is a projection of the Hono routes

[`stack.md`](../../standards/stack.md) declares the API Worker to be the single contract for web, MCP and skills. That was declared, never published: the contract existed only as Hono handlers with inline `parseOrThrow(zodSchema, …)` calls, and nothing outside the app could read it ([Roxabi/roxabi-boilerplate-cf#169](https://github.com/Roxabi/roxabi-boilerplate-cf/issues/169)).

**Implementation and scope:** this decision applies to kit-owned `example-api` routes, excluding the Better Auth passthrough. The committed snapshot and generation/check scripts are the delivered contract surface; they are not a public Worker endpoint or proof of external deployment.

## Context

Two properties matter for a kit whose thesis is that many products compose one kernel:

1. a machine-readable contract that a SPA, an MCP server or a skill can consume;
2. a contract whose request validation and declared response types share the running route definitions, reducing drift without claiming the type system proves every runtime response or discovers every undeclared route.

## Alternatives considered

| Option | Contract source | Verdict |
|---|---|---|
| **A** `@hono/zod-openapi` — `OpenAPIHono` + `createRoute` | The route schema **is** the validator | **Accepted** |
| **B** `hono-openapi` / `describeRoute` annotations | Annotation beside the handler | Rejected |
| **C** Bespoke generator over `app.routes` + a metadata registry | Hand-declared metadata | Rejected |

B and C share one defect: the document is a second declaration. A drift gate can only compare the document to itself, so a spec that claims `200 { item }` next to a handler returning `{ items }` stays green forever, and every new endpoint depends on a human annotating it truthfully. C additionally puts a generator in kit-owned code and forgoes ecosystem tooling.

A costs a one-time rewrite of every route file and makes the failure mode compile-time.

## Decision

### D1 — Routes are declared with `createRoute`; the schemas are the validators

`apps/example-api` is an `OpenAPIHono` app. Each kit-owned endpoint is a `createRoute({ method, path, security, middleware, request, responses })` registered with `app.openapi(route, handler, hook?)`. `parseOrThrow` inside a route file is a regression; it remains the right helper outside routes. `/api/auth/*` is a Hono `.all()` passthrough owned by Better Auth, not a `createRoute` operation.

### D2 — Error envelope parity is mandatory

The validation hook throws `AppError.fieldErrors(message, zodFieldErrors(error))`, so the response stays `{ error: { code: 'VALIDATION_ERROR', message, details: { fieldErrors } }, requestId }`. Routes that used a custom message keep it via `invalidRequest('<message>')`. Migration to OpenAPI MUST NOT change any status, code, message, detail or header.

### D3 — The document is committed and gated, not served

`docs/kit/openapi/example-api.json` is generated by `scripts/kit/gen-openapi.ts` and checked by `bun run openapi:check` inside `validate:full`. No public `/openapi.json` endpoint: the private API gains no new surface, and the snapshot is reviewable in a diff. The gate protects commit hygiene; contract truth is protected by the type system and the runtime validators.

### D4 — Security schemes mirror the middleware

`session` (Better Auth cookie) and `apiKey` (org-bound `sk_` bearer) are declared components. A route that enforces a session declares `sessionOnlySecurity` (`sk_` rejected with 403; [ADR-0002](./0002-session-hmac-interim-vs-better-auth.md) dual path). Dual-credential routes declare `sessionOrKeySecurity`.

### D5 — `@kit/api-client` stays generic

It keeps `fetch` + error envelope + cookie credentials, with no route constants and no generated types. One contract surface in the kit; a typed client generated from the document is a product or later-ADR decision.

### D6 — Response schemas declare exact shapes

A response schema lists the fields the handler actually returns. `.loose()` is prohibited: it publishes `additionalProperties: true` instead of the contract, and its `[x: string]: JSONValue` index signature is incompatible with any optional field typed `| undefined`, so it fails the compiler for the wrong reason. Security requirement lists are shared typed constants (`sessionOrKeySecurity` / `sessionOnlySecurity`) — an inline `[{ session: [] }]` infers `never[]`, which does not satisfy `SecurityRequirementObject[]` and silently collapses route generic inference.

The `.loose(` half is a banned-string check in `scripts/kit/check-banned-strings.sh` (`\.loose\(` scoped to `apps/example-api/src/routes/**`). It catches that literal call in the contract declarations; it does not catch `.passthrough(`, `.catchall(`, `looseObject(`, `.loose` with a space, or any other open-ended shape. The shared-security-constant half remains convention: the `never[]` inference is a compiler symptom where the handler reads `c.req.valid()`, not a gate.

## Consequences

- Adding a kit-owned endpoint without declaring its contract is a regression. `OpenAPIHono` still inherits Hono's `.all()` / `.get()` / `.post()`, so an undeclared path remains possible by construction.
- Request/response shapes are visible to reviewers as a JSON diff.
- Widening a request schema to make the document tidy is now visibly an authority change (flows bodies stay `.strict()`).
- One-time cost: every route file rewritten; `c.req.valid(...)` replaces manual `c.req.json()` + parse.
- `@hono/zod-openapi` (and its `zod-to-openapi` dependency) is now a runtime dependency of the API app.

## Non-goals

- Serving the document from the Worker
- Generating a typed client in the kit
- New endpoints, renamed routes, or changed status codes
- OpenAPI for `apps/mcp-example` (MCP has its own tool catalogue contract)
- Product domain strings in the document
- Better Auth `/api/auth/*` — Better Auth owns that surface; the app registers it with Hono `.all()`, not `createRoute`. Session minting is documented in [`stack.md`](../../standards/stack.md)

## Acceptance

- Every kit-owned `example-api` endpoint is declared with `createRoute`; no `parseOrThrow` remains in route files
- 400 / 401 / 403 / 404 (and 409 / 429 where reachable) are documented per route
- `bun run openapi:check` fails on a stale snapshot and runs in `validate:full`
- The pre-existing HTTP test suite passes unmodified
