## Goal

Ship Better Auth as the kit UI session path behind an extended **`SessionPort`**, with dual-path **Bearer `sk_…`** unchanged, so product apps promote without forking `@gosilex/auth`.

**Kit M3 subset (this issue):** BA email/password + dual-path green + exported BA adapter. Optional env-gated GitHub provider OK. **OAuth org membership gate + recheck cron = product** (`silex-share#12`), not kit done.

### D5 — Extended port API (normative for S0)

```ts
// Conceptual — exact names in plan may alias, semantics locked

type SessionPayload = { sub: string; email: string; exp: number }

type SessionPort = {
  /** HMAC path: sign payload → token. BA path: may throw or be unused (handler issues cookie). */
  sign(payload: SessionPayload, secret: string): Promise<string>
  /** HMAC path: verify bare token. BA path: may be unused if resolveSession is implemented. */
  verify(token: string, secret: string): Promise<SessionPayload | null>
  /** Preferred session resolve for dual-auth (BA: getSession({ headers })). HMAC: parse cookie + verify. */
  resolveSession(input: {
    cookieHeader?: string | null
    headers?: Headers
    secret?: string
    cookieName: string
  }): Promise<SessionPayload | null>
  cookieHeader(token: string, opts?: { secure?: boolean; maxAge?: number }): string
  clearCookieHeader(opts?: { secure?: boolean }): string
}

type DualAuthPorts = {
  /** HMAC session secret; optional when adapter uses BA-only resolveSession without secret. */
  secret?: string
  cookieName: string
  sessions?: SessionPort
  findApiKeyByPrefix: (prefix: string) => Promise<ApiKeyRecord | null>
}
```

- HMAC adapter: implements all methods; `resolveSession` = parse cookieName + `verify`.
- BA adapter: `resolveSession` → `auth.api.getSession({ headers })` → map user/session to `SessionPayload`; `sign` unused; cookie set/clear via BA handler (cookieHeader/clear may clear-by-name only).
- `resolveDualAuth`: Bearer first (unchanged); else `sessions.resolveSession(...)` — **never** hardcode cookie name.

## Expected Behavior

1. Env sets `AUTH_SESSION_ADAPTER=better-auth` + BA secrets + D1; migrations include BA schema.
2. User opens example-web `/login`, submits email/password.
3. Request hits BA routes under `/api/auth/*` (per-request auth instance with CF bindings).
4. BA sets HttpOnly session cookie (`Secure` when not local, `SameSite=Lax`, `Path=/`, name = SSoT).
5. Subsequent API calls with `credentials: 'include'` pass `requireAuth` → subject from BA session.
6. MCP client with `Authorization: Bearer sk_…` still authenticates via hash lookup; mint/revoke keys still require **session** method.
7. Mutations with session cookie require Origin allowlist (`originGuard` using same cookie name).
8. Logout clears BA session; subsequent `/api/me` → 401 with existing error envelope.
9. Product app: mount BA + inject port + own migrations — **no kit source fork**.

### Identity / seed (locked)

- When adapter=`better-auth`, **BA user id is `AuthIdentity.subject`** for session path.
- Demo seed creates BA-compatible user (BA admin API or direct seed into BA tables) so login subject is stable for `api_keys` / notes.
- Kit legacy `users` PBKDF2 table: **not used for session login** when adapter=BA; may remain for hmac adapter mode only. No dual-login against both tables.

## Edge cases

| Case | Handling |
|---|---|
| adapter=better-auth, missing BA secret | Fail closed |

| Bearer + cookie both present | Prefer Bearer (current order) |
| Cookie name mismatch | Impossible if SSoT used everywhere — tests enforce |
| GitHub env absent | OAuth unused; email/password works |
| adapter=hmac | Current HMAC login path preserved for break-glass / tests |
