#58 — Architecture shapes

Three mutually exclusive approaches to BO user provisioning + first login

Shape 1 · recommended

Kit admin routes + EmailPort

  • POST /api/admin/users creates BA user (seed-style insert + random unusable password hash)
  • Atomic platformRole + memberships via existing repos
  • Welcome token = BA verification (reset path) or kit prefix; email via @gosilex/email
  • Mirrors invites D7 (rate limit, email-fail cancel)
  • BA org invite surface stays DENY
Shape 2

Better Auth admin plugin

  • BA creates/lists users natively
  • Still need kit for platform roles, multi-membership, ceiling, EmailPort
  • Couples to BA admin surface + may fight disableSignUp
  • Eval-only per frame
Shape 3

Invite-only bootstrap

  • Extend org invite: unknown email → create user + welcome
  • No first-class multi-org + plane from BO
  • Does not deliver JTBD (staff provision from /admin/users)
